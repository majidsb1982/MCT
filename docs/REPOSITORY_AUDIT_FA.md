# گزارش بررسی و سامان‌دهی مخازن GitHub

تاریخ بررسی: 2026-10-16

## تصمیم‌های ایمن

این گزارش بر اساس فهرست مخازن و فایل‌های README/ورودی שנ بررسی شده‌اند تهیه شده است. این بررسی هنوز جایگزین مقایسه کامل همه فایل‌ها، تاریخچه commitها و اجرای تست‌ها نیست.

### خانواده مدیریت کلاس

| مخزن | یافته | اقدام پیشنهادی |
|---|---|---|
| `MCT` | برنامه JavaScript بدون build، منتشرشده در GitHub Pages با آدرس majidsb1982.github.io/MCT | فعلاً حفظ به‌عنوان مقصد انتشار تا پایان مهاجرت و تست |
| `My-Class-Track` | PWA آفلاین؛ امکانات مشخص پیگیری دو نوبت، شهریه هر جلسه، تکالیف، یادآوری و گزارش؛ دارای CI و آزمون‌های پروژه طبق README | نامزد اصلی برای مقایسه قابلیت‌ها و انتخاب نسخه مرجع |
| `Mctgem` | برنامه React 19 + TypeScript + Vite؛ ساختار متفاوت و امکانات بیشتر توصیف‌شده در README | استخراج قابلیت‌های منحصربه‌فرد؛ ادغام مستقیم فایل‌ها بدون مهاجرت معماری توصیه نمی‌شود |
| `Mctgem-v13` | نسخه قدیمی‌تر خانواده Mctgem با تغییرات UI/UX | نگهداری فقط برای بازیابی قابلیت‌هایی که در نسخه جدیدتر نیستند |
| `class-tracker-pro` | برنامه آفلاین با ساختار src/pages، IndexedDB و تست‌ها؛ README امکانات اعضا، جلسات، نقش‌ها و گزارش‌ها را معرفی می‌کند | مقایسه قابلیت‌ها و تست‌ها پیش از تصمیم نهایی |
| `group-therapy-management` | برنامه مستقل موبایل‌محور با فایل‌های ساده و پشتیبان JSON؛ قابلیت‌های هم‌پوشان | بررسی به‌عنوان منبع قابلیت، نه حذف فوری |
| `MCT-v16` | مخزن خالی | نامزد پاک‌سازی؛ ابتدا بررسی وابستگی‌ها و تنظیمات GitHub |

### پروژه‌های مستقل

- `forklift-spare-parts-system`: پروژه مستقل انبار و قطعات لیفتراک؛ با برنامه کلاس ادغام نشود.
- `mlmvpn-cloud-tunnel`: مخزن خصوصی و مستقل؛ README آن می‌گوید موقتی است و خودکار بازسازی می‌شود. حذف یا تغییر آن بدون بررسی کاربرد جاری انجام نشود.
- مخزن با نام `-`: فایل README در مسیر اصلی پیدا نشد؛ تا تعیین محتوا و هدف، حذف نشود.

## اصول لازم پیش از ادغام

1. از مخزن مقصد و فایل‌های داده/پیکربندی نسخه پشتیبان نگهداری شود.
2. قابلیت‌ها و فایل‌ها با مقایسه درخت فایل، hash، تاریخچه commit و تست‌ها بررسی شوند؛ شباهت نام یا README به‌تنهایی دلیل تکراری بودن نیست.
3. داده‌های محلی کاربران در مرورگر ممکن است به origin و ساختار ذخیره‌سازی وابسته باشند؛ تغییر مقصد انتشار یا کلیدهای ذخیره‌سازی می‌تواند دسترسی به داده‌های قبلی را مختل کند.
4. قبل از تغییر `MCT`، لینک GitHub Pages، مسیرهای نسبی، فایل‌های Service Worker/cache و نسخه‌گذاری CSS/JS باید تست شوند.
5. ابتدا مهاجرت در شاخه جداگانه و با تست انجام شود؛ حذف مخزن فقط پس از تأیید برابری قابلیت‌ها و حفظ تاریخچه/نسخه پشتیبان.
6. داده‌های محرمانه گروه درمانی نباید به گزارش‌های عمومی یا مخزن عمومی منتقل شوند.

## نتیجه فعلی

در این مرحله هیچ مخزنی حذف نشده و برنامه منتشرشده تغییر نکرده است. برای تصمیم قطعی درباره ادغام، باید فهرست کامل فایل‌ها و محتواهای کلیدی همه نسخه‌ها در دسترس باشد و تست واقعی اجرا شود. اولویت پیشنهادی: مقایسه `My-Class-Track` با `MCT`، سپس `Mctgem` و `class-tracker-pro`؛ در پایان تصمیم درباره مخازن قدیمی و خالی.
